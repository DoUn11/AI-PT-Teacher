# 자세 보정(calibration) 작업 인수인계

최종 갱신: 2026-11-22 (약한 조건 개선 실험: 니업 다리 긴장, 푸시업 Day32 일반화. 사이드 크런치 시선 제외 결정).

## 목표
AI PT쌤(대학 과제). 라벨 데이터(올바른 자세 / 틀린 자세)에서 관절 각도를 뽑아 운동별 **정답 각도와 오차범위**를 정하고,
각도가 벗어난 정도로 점수를 매겨 **점수가 낮은 부분을 피드백**한다. 결과는 `analyzer`의 운동 설정 JSON 형식(`--thresholds`)으로 내보내는 것이 목표.

## 확정한 결정
- 운동 3종만: **푸시업, 스탠딩 니업, 스탠딩 사이드 크런치** (스쿼트 제외).
- 카메라는 전부 **정면**. 푸시업은 순수 정면 뷰가 없어 **A뷰(`view1`, 머리 쪽 대각선)를 정면 기준**으로 쓴다 (C=`view3`는 측면).
  **서 있는 운동(니업, 사이드 크런치)은 반대로 C뷰(`view3`)가 정면**(사람이 카메라를 마주 봄)이고 A는 거의 측면이다 -> C를 기준으로 쓴다.
- 판정 단위: 라벨 한 개(16프레임 구간)에서 각도의 **최솟값/최댓값**(+중앙값).
- 정답 각도는 데이터 분포에서 정하고, 오차범위에 따라 점수.
- 분할: **촬영일(Day) 단위**. 하루씩 빼고 검증(leave-one-day-out). 푸시업은 Validation(Day32)을 최종 시험으로 따로 쓴다. 니업/사이드 크런치는 Training 6일(Day01,05,09,13,23,27)만 있다.
- 푸시업은 **팔·어깨 각도만** 사용 (척추, 고개 조건은 평가 제외). 니업/사이드 크런치는 전신 관절 사용 예정.
- 모델: 웹(`frontend/`)은 **MediaPipe(33점)**, 로컬 분석기(`analyzer/`)는 YOLO11-pose(17점). 라벨(24점)에서 두 모델에 공통인 관절만 쓴다
  (코, 귀, 어깨, 팔꿈치, 손목, 골반, 무릎, 발목). 목/등/허리는 어깨·골반 중점으로 대체. 프론트엔드는 현재 코/귀를 안 가져오므로 추가가 필요.
- **사이드 크런치 "시선 정면"은 점수와 측정에서 뺀다** (MP 기준 0.67로 너무 자주 틀림). 설정 JSON에서는 지우지 말고 비활성으로 표시한다.
  그래서 시선만 틀린 사이드 크런치는 앱에서 정자세로 나온다 (감수하기로 함).
- **시선은 모든 운동에서 뺀다** (니업 시선 1회 0.77, 사크 시선 0.67, 푸시업 고개 조건은 원래 제외). 설정 JSON에서 enabled: false.
  단 **코/귀 랜드마크는 여전히 필요하다**: 사크 척추 중립의 최선 특징이 head_pitch_min(1회 0.77)이고,

## 1회 단위 평가 (2026-11-22, `rep_features.py`)
앱은 동작 1회마다 점수/피드백을 낸다(`frontend/src/analysis.js` RepCounter, ThresholdJudge). 그래서 MP 좌표를 1회씩 잘라 다시 평가했다.

| 사크 | 손 머리 뒤 | 0.96 | elbow_angle_med > 103° | 강 |

  즉 지금 앱은 깔짝 푸시업 대부분을 1회로 세지 않아서 점수도 피드백도 안 나온다. 정자세 회의 팔꿈치 최솟값 95%가 141°라
  정자세도 일부 안 세진다. count_threshold를 올리고(예: 145~150°) 깊이는 점수(감점)로 판정하는 쪽이 맞다. 웹캠 거리/각도에 따라 다르니 실측 필요.

## 설정 JSON 형식 확장 (2026-11-22, 끝남)
`form_checks` 항목에 칸을 추가했다 (파이썬 `aipt_analyzer/config.py`, `judges.py` / JS `frontend/src/analysis.js` 둘 다, 생략하면 예전 동작).
- `enabled` (기본 true): false면 측정·감점·피드백 안 함. **니업 다리 긴장, 사크 시선**에 쓴다.
- `live` (기본 true): false면 실시간 경고 없이 1회 끝난 뒤 피드백만. 약한 조건에 쓴다.
- `full_at`: limit에서 0, full_at에서 penalty까지 선형 감점 (기준 근처 애매한 판정은 조금만 깎음).
- `tier`: "strong" | "medium" | "weak" (기록용). `stat`에 "mean" 추가 (`direction`: "above" | "below" 필요).
- 최상위 `score_step` (기본 1): 1회 점수 반올림 단위. **pushup.json은 10**으로 켰다 (squat.json은 기존 테스트 때문에 그대로).
- 반올림은 양쪽 모두 은행원 반올림(파이썬 round와 같음)으로 맞췄다. 테스트: 파이썬 53개, 프론트 25개 통과.

등급 -> 칸 (초안, 숫자는 데이터가 아니라 정한 값):
| 등급 | penalty | full_at | live |
|---|---|---|---|
| strong | 30 | 없음 (바로 감점) | true |
| medium | 20 | 정상 범위 끝(5/95%)쯤 | true |
| weak | 10 | 기준에서 꽤 먼 값 | false |
| 제외 | - | - | enabled: false |

(막혀 있던 특징 추가는 아래 절에서 해결.) 위 등급표 숫자는 `calibrate.py`의 TIER에 있다.

## 파일
- `extract_pushup.py` : 푸시업 2D 라벨 -> 구간 요약 CSV (A뷰, C뷰). numpy만 필요.

- `mediapipe_extract.py` : 라벨 있는 클립 이미지에 MediaPipe 실행 -> 날짜별 npz (33점 원좌표). 중단 후 이어 하기 가능.
- `mediapipe_features.py` : npz -> 구간 요약 CSV (`M_`=32장, `M16_`=라벨과 같은 16장). 라벨 CSV 열도 같이 붙인다.
- `evaluate_conditions.py` : 조건별 분리도 평가 (하루씩 빼고 검증, 특징 1개/nested/로지스틱). pandas, scikit-learn 필요.

- `rep_features.py` : MP 좌표를 동작 1회 단위로 잘라 1회마다 특징 요약 (`_work\out_rep\`).
- `calibrate.py` : 1회 데이터 -> 운동 설정 JSON (`--out ../aipt_analyzer/configs`). 조건/등급 표는 파일 안 EXERCISES, TIER.
- `replay_app.py` : MP 좌표를 앱 Analyzer에 넣어 회 수/점수/피드백 확인 (`--mp mp --labels out_mp --dt 0.15 0.25 0.4`).
- `extra_features.py` : 시간 특징(T_), 사람별 정규화(P_, Q_) 열을 더한 CSV를 만든다 (`_work\out_extra\`).
- 이미 만들어진 결과(PC, `D:\데이터\AI_PT_선택운동\_work\`): `out\`(푸시업 2D), `out3d\`(3D), `out_standing\`(서 있는 운동 라벨),
