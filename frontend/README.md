# AI PT쌤 프런트엔드

학교 팀 프로젝트의 웹 화면이다. 별도 프레임워크나 빌드 도구 없이 HTML | CSS | JavaScript 모듈로 구성하며, 기존 FastAPI 백엔드 API를 사용한다.

## 로컬 실행

프런트엔드는 **5173**, 백엔드는 **8000** 포트를 사용한다. 포트는 로컬 개발 기본값이며 배포 주소를 의미하지 않는다.

먼저 저장소의 [백엔드 실행 안내](../backend/README.md)에 따라 백엔드를 실행한다. 이어 프런트엔드를 실행한다.

Windows PowerShell:

```powershell
cd frontend
python -m http.server 5173 --bind localhost
```

macOS | Linux:

```sh
cd frontend
python3 -m http.server 5173 --bind localhost
# 또는 Node.js와 Python 3가 설치되어 있다면
npm start
```

브라우저에서 [http://localhost:5173](http://localhost:5173)을 연다. 회원가입 후 로그인한다. 데모 계정이나 임의 운동 기록은 포함하지 않는다. 파일을 직접 여는 `file://` 방식은 지원하지 않는다.

### 백엔드 연결

- 기본 주소는 `src/api.js`의 `DEFAULT_BASE`인 `http://127.0.0.1:8000`이다. 로그인 화면에는 서버 주소 입력란이 없다.
- 다른 서버를 사용할 때는 `DEFAULT_BASE`를 변경하고 백엔드의 CORS 허용 출처를 확인한다. 현재 백엔드 기본 설정은 `http://localhost:5173`을 허용한다.
- `127.0.0.1`은 브라우저를 실행하는 기기 자신이다. 다른 기기나 배포 환경에서는 실제 서버 주소와 HTTPS 설정이 필요하다.
- 액세스 토큰은 `sessionStorage`에 저장한다. 새로고침 시 인증을 확인하며, 탭을 닫거나 토큰이 만료되면 다시 로그인해야 한다. 기존 백엔드의 토큰 유효기간은 기본 30분이다.

## 화면과 지원 범위

| 화면 | 내용 |
|---|---|
| 로그인 &#124; 회원가입 | 중앙 정렬 폼, 이메일과 비밀번호 입력, 회원가입 시 닉네임 입력 |
| 홈 | 연속 운동일, 오늘의 **약점 기반 추천**, 이번 주 활동, 최근 운동, 기기(카메라·분석기) 상태, **내 약점 부위 몸 그림** |
| 운동 | **운동 카드**(푸시업·니업·사이드 크런치: 지금 목표, 지난 결과, 내 기록 기준 평가) → 카드를 누르면 **목표 설정**(세트·횟수·휴식, 강도 올리는 속도 천천히/보통/빠르게, 자동 여부, "목표 없이 자유롭게") → 시작하면 **왼쪽 큰 영상(분석 화면 / 원본), 오른쪽 패널**: 세트 진행(몇 세트째, 세트 내 횟수), 준비·휴식 카운트다운(건너뛰기), 횟수, 깊이 게이지, 자세 체크. 목표를 다 채우거나 종료하면 **리포트로 자동 이동**. 연결 기록은 아래. 좁은 화면(980px 이하)에서는 위아래로 쌓인다. 백엔드에 `MQTT_URL` 설정과 PC의 `./run_mqtt.sh` 필요 |
| 기록 | 운동 종류별 필터, 점수 추이, 약점 부위, 세션 목록. 세션을 누르면 **세션 리포트**(`?tab=dashboard&session=ID`) |

화면과 API가 어떤 사용 흐름에서 나왔는지는 [../docs/USECASES.md](../docs/USECASES.md).

- 오른쪽 위 버튼으로 라이트 | 다크를 전환한다. 테마는 브라우저에 저장한다.
- 시작은 초록색 재생 버튼, 종료는 빨간색 정지 버튼이다. 영상 위 상태는 정지 `Ⅱ`, 실행 `▶▶`로 표시한다.
- 브라우저 웹캠 분석 화면은 없앴다. 자세 분석은 Pi 카메라와 PC 분석기만 한다 (`?tab=camera` 같은 옛 주소는 홈으로 간다).

### 운동 종목

현재 화면에 노출하는 종목은 세 가지다. 종목 목록은 `src/dom.js`의 `EXERCISE_LABELS`에서 관리한다.

| 종목 | 현재 상태 |
|---|---|
| 푸시업 | 분석 설정과 백엔드 저장 지원 |
| 스탠딩 니업 | 분석 설정과 백엔드 저장 지원 |
| 스탠딩 사이드 크런치 | 분석 설정과 백엔드 저장 지원 |

스쿼트와 런지 | 플랭크 | 크런치는 화면 목록에서 뺐다. 백엔드의 `squat` 종목은 남아 있다. 서버에 저장된 스쿼트 기록은 기록 화면에 표시하지 않는다.

### 피드백 문구

문구는 `configs/messages.ko.json`에 있고, 조건과 감점은 분석기(`../analyzer/aipt_analyzer/configs/<종목>.json`의 `form_checks`)에 있다. 한 번(rep)이 끝나면 `100 − 감점`을 10점 단위로 깎아 점수를 계산하고 해당 문구를 붙인다. 실시간이 켜진 항목은 운동 중 화면에도 바로 표시한다. 감점은 강도에 따라 강 30 | 중 20 | 약 10이다.

**푸시업**

| 문구 | 조건 | 감점 | 실시간 |
|---|---|---|---|
| 더 깊이 내려가세요 | 팔꿈치 각도가 목표 129.7°보다 클 때 (1°당 1.134점, 최저 90점) | 깊이 | |
| 손 간격을 너무 넓히지 마세요 | 손 간격 비율 평균이 1.938 초과 | 20 | 켬 |
| 손을 가슴 옆에 두세요 | 어깨 각도 최솟값이 58.1° 초과 | 10 | |
| 몸을 일직선으로 유지하세요 | 꺼짐. 측면 촬영용이라 정면 카메라에서는 사용하지 않음 | 20 | |

**스탠딩 니업**

| 문구 | 조건 | 감점 | 실시간 |
|---|---|---|---|
| 무릎을 골반 높이까지 올리세요 | 발목 들림 최댓값이 0.678 미만 | 30 | |
| 상체를 숙이지 말고 곧게 세우세요 | 몸통 비율 최솟값이 1.313 미만 | 20 | 켬 |
| 시선은 정면을 보세요 | 꺼짐 | 10 | |
| 다리를 내릴 때도 힘을 유지하세요 | 꺼짐 | 10 | |

**스탠딩 사이드 크런치**

| 문구 | 조건 | 감점 | 실시간 |
|---|---|---|---|
| 양손을 머리 뒤에 두세요 | 양쪽 팔꿈치 각도 평균이 107.3° 초과 | 30 | 켬 |
| 무릎을 몸통 옆으로 들어 올리세요 | 무릎 옆 이동량 최댓값이 0.332 미만 | 30 | |
| 팔꿈치와 무릎을 더 가깝게 모아 보세요 | 무릎 간격 최솟값이 0.148 초과 | 20 | |
| 고개를 숙이지 말고 정면을 보세요 | 머리 기울기 최솟값이 −0.097 미만 | 10 | |
| 시선은 정면을 보세요 | 꺼짐 | 10 | |

- 니업과 사이드 크런치의 깊이 항목은 감점이 0이라 점수에 영향이 없다.
- 기준값은 AI Hub 데이터로 `calibrate.py`가 만든 값이며 웹캠 실측 검증 전이다. 설정 파일을 손으로 고치지 말고 `calibrate.py`를 수정해 다시 만든다.
- 상태 문구(`phase.*`, `no_person`)는 영상 위 진행 상태 표시에 쓴다.

## 리포트와 기록

- **세션 리포트:** 점수 링, 이전 세션 대비 점수 변화, **몸 그림**(팔·몸통·다리를 약점 정도에 따라 초록 → 노랑 → 빨강으로 칠함), 부위별 등급과 지적 횟수, "다음 운동 포인트" 한 가지, 자주 지적된 자세, 반복별 점수 막대, 반복별 상세 표. 몸 그림 위에 마우스를 올리면 해당 부위 줄이 강조된다.
- **기록:** 요약 수치는 백엔드의 종료된 세션 통계, 점수 추이와 부위 약점은 `/workouts/insights`의 최근 30세션을 쓴다. 목록은 전체 최근 100건을 받아 선택 종목으로 필터링하고, 반복이 없는 세션은 뺀다. 따라서 누적 통계와 화면의 건수는 다를 수 있다.
- 부위 값이 없는 예전 기록도 피드백 코드에서 부위를 추정해(서버가 처리) 같은 화면에 나온다.

현재 날짜 선택과 기간 조회 UI는 없다. 백엔드에는 통계의 `since` 조건만 있고, 기록 목록의 날짜 범위 필터는 없다. 전체 기록 페이지 조회 및 날짜 필터는 추후 API 연동 작업이다.

## 검증

Node.js 20 이상에서 실행한다. 테스트용 npm 패키지 설치는 필요 없다.

```sh
cd frontend
npm test
```

자동 테스트 35개는 분석 정보와 세트 진행 화면 값, 리포트·홈·기록의 값 계산(부위 색, 추세, 추천 문구), 목표 평가 문구를 확인한다. 화면 흐름은 별도로 헤드리스 브라우저로 확인했다.

UI는 로그인 | 회원가입 | 홈 | 운동 | 기록을 320px | 390px | 768px | 1280px, 라이트 | 다크, 대표 150% 확대 조건에서 확인했다. 버튼 정렬, 드롭다운 너비와 키보드 조작, 표, 빈 기록 및 추가 예정 상태를 검수했다. 격리 브라우저의 모의 API 검사와 로컬 백엔드의 실제 계정 인증을 구분하여 확인했다.

실제 사람이 Pi 카메라 앞에서 운동하며 점수 정확도와 전체 저장 흐름을 확인하는 검증은 별도로 필요하다. UI 검수와 자동 테스트 통과가 실제 동작 분석 정확도 검증을 대신하지 않는다.

## 알려진 제약과 추후 작업

- 분석 기준값은 분석기 설정이 정하고 웹은 문구와 화면만 맡는다. 보정 값은 실제 동작 검증이 필요하다.
- 배포 주소, HTTPS와 CORS, 만료 토큰 처리, 추가 종목, 날짜 조회는 팀의 후속 작업이다. 개발 할 일은 UI에 상시 노출하지 않고 이 문서에서 관리한다.
- `.qa/`, 로컬 실행 환경, 테스트 DB, 계정 정보와 서버 로그는 Git에 포함하지 않는다. 배포 화면에 미리보기 경로나 샘플 데이터는 제공하지 않는다.

이번 변경은 `frontend/` 범위이며 백엔드 | 분석기 | 라즈베리파이 코드는 변경하지 않는다.
