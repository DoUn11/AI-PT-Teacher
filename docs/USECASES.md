# AI PT쌤 유즈케이스와 파이프라인

집에 카메라(Raspberry Pi)를 세워 두고, 화면을 보며 운동하면 **어느 신체 부위의 자세가 약한지** 알려 주는 홈트 코치.
이 문서는 화면과 API가 어떤 사용 흐름에서 나왔는지 적는다. 흐름이 바뀌면 이 문서부터 고친다.

## 사용자

운동 자세를 봐 줄 사람이 없는 홈트 사용자. 운동 중에는 손이 자유롭지 않고(마우스/키보드 불가), 끝난 뒤에 "그래서 뭘 고치면 되지?"를 알고 싶어 한다.

## 유즈케이스

| # | 유즈케이스 | 사용자가 얻는 것 | 화면 | 주 API |
|---|---|---|---|---|
| UC1 | 가입하고 로그인한다 | 내 기록이 쌓이는 계정 | 로그인 | `POST /auth/register`, `/auth/login` |
| UC2 | 오늘 뭘 할지 안다 | 연속 운동일, 이번 주 활동, **약점 기반 추천** | 홈 | `GET /workouts/insights` |
| UC3 | 기기가 준비됐는지 본다 | 카메라·분석기가 켜졌는지 한눈에 | 홈 (기기 상태) | `GET /camera/status` |
| UC4 | 운동 카드를 고르고 목표를 정한다 | 운동별 **세트 × 횟수 · 휴식**, 내 기록으로 정한 시작값, **강도를 올리는 속도(천천히/보통/빠르게)** | 운동 (카드 → 설정) | `GET/PUT /workouts/plans` |
| UC5 | 세트를 하며 실시간으로 교정받는다 | 준비 카운트다운, 세트·횟수 진행, 세트 사이 휴식(건너뛰기 가능), 빨갛게 변하는 관절선 | 운동 (영상 + 패널) | `POST /camera/session/start`, `/skip-rest`, `GET /camera/analysis` |
| UC6 | 운동을 끝내고 리포트를 본다 | 목표 결과(세트별 횟수·점수), **몸 그림에 부위별 약점**, 다음에 고칠 점, **다음 운동 목표**, 반복별 점수 | 리포트 (목표를 다 채우거나 종료하면 자동 이동) | `POST /camera/session/stop`, `GET /workouts/sessions/{id}/report` |
| UC7 | 좋아지고 있는지 확인한다 | 점수 추이, 부위별 추세(좋아지는 중/나빠지는 중), 지난 세션 대비 점수 | 기록 | `GET /workouts/insights`, `/workouts/sessions` |

### UC4~UC6 상세 (핵심 흐름)

1. **운동** 탭에는 운동 카드(푸시업/니업/사이드 크런치)가 있다. 카드에는 지금 목표(예: 3세트 × 10회 · 휴식 60초), 자세를 보는 부위, 지난번 결과, 내 기록 기준 평가가 보인다. 분석기는 카드에서 시작하기 전에는 아무것도 세지 않는다.
2. 카드를 누르면 **목표 설정**: 세트(1~운동별 최대), 한 세트 횟수, 세트 사이 휴식, 강도 올리는 속도와 자동 여부. 처음이면 목표 없이 한 기록의 80% 또는 운동별 기본값(푸시업 3×8, 니업·사이드 크런치 3×12)에서 시작한다. 시작 전에 값이 바뀌었으면 저장한다.
3. **시작**: 분석기가 세션을 열고(목표도 함께 기록), 5초 동안 자세 잡을 시간을 준다 (`ready`). 이 동안은 횟수를 세지 않는다.
4. 세트 진행(`working`): 목표 횟수를 채우면 세트가 끝나고 **휴식(`resting`)** 카운트다운이 시작된다. 휴식 중 움직임은 세지도 올리지도 않는다. 건너뛰면 바로 다음 세트가 시작된다.
5. **마지막 세트를 채우면 저절로 종료**된다. 도중에 종료를 눌러도 한 만큼은 기록된다. 분석기가 끝난 세션의 id를 알리면 웹이 **리포트로 자동 이동**한다.
6. 리포트는 목표 결과 → 부위별 약점 → "다음에 고칠 점" → 자주 지적된 자세 → **다음 운동 목표**(왜 그렇게 정했는지 포함) 순이다. 자동 조정이 꺼져 있으면 제안과 "적용" 버튼이 나온다.

### 목표(강도) 자동 조정

자세가 좋을 때만 늘린다. 목표를 다 채우고(완료율 100%) 평균 점수가 75점 이상이면 '잘 한 세션'이다.

| 속도 | 올리는 조건 | 올리는 양 |
|---|---|---|
| 천천히 | 잘 한 세션이 **3번 연속** | +1회 |
| 보통 | 잘 한 세션이 **2번 연속** | +1회 |
| 빠르게 | 잘 한 세션이 **1번** | +2회 |

- 한 세트 횟수가 운동별 상한(푸시업 15, 니업·사이드 크런치 20)에 닿으면 세트를 하나 늘리고 횟수를 상한의 70%로 되돌린다. 세트는 운동별 최대 5개.
- 완료율 70% 미만이거나 평균 점수 55점 미만인 세션이 나오면 횟수를 1회 낮춘다 (하한: 푸시업 4, 나머지 6).
- 다 채웠지만 자세가 75점 미만이면 **늘리지 않는다**. 목표를 다 못 채웠으면 그대로 둔다.
- 사용자가 세트·횟수를 직접 바꾸면 그 전 기록은 새 목표와 무관하므로 평가를 처음부터 다시 쌓는다. 같은 값으로 다시 저장하면(시작 버튼) 기록은 유지된다.
- "자동으로 올리기"를 끄면 목표는 그대로이고 제안만 한다.

### 대안 흐름

| 상황 | 동작 |
|---|---|
| 분석기가 꺼져 있다 | 시작/종료/운동 선택 버튼이 막히고 켜는 방법을 알려 준다 (`409`) |
| 이미 운동 중에 시작을 또 누른다 | `409 이미 운동 중이에요` |
| 종료를 눌렀는데 분석기가 응답하지 않는다 | 12초 뒤 "응답하지 않아요" |
| 반복이 하나도 없이 끝났다 | 리포트는 "완료된 반복이 없어요 + 다시 하기", 기록 목록에서는 숨긴다 |
| 세션을 모르는 예전 분석기 | 켜자마자 세션이 열리는 예전 방식으로 동작 (시작/종료 버튼 없음). 목표 설정 화면은 분석기를 업데이트하라고 안내하고 시작을 막는다 |
| 목표 없이 하고 싶다 | 설정 화면의 "목표 없이 자유롭게": 세트 구분 없이 종료할 때까지 센다. 강도 조정에는 반영되지 않는다 |
| 새로고침하거나 다른 탭에 갔다 왔는데 운동 중이다 | 운동 탭이 열리면 진행 중인 세션을 찾아 바로 영상 화면으로 돌아간다 |
| 예전 기록처럼 부위 값이 없다 | 피드백 코드가 가리키는 부위를 일정한 값(0.7)으로 칠해 같은 화면에서 본다 |

## 파이프라인

```text
 Raspberry Pi 카메라                       PC                                    서버                       브라우저
 ──────────────────       ┌──────────────────────────────────────┐   ┌──────────────────────┐   ┌─────────────────────┐
  pi_mqtt_publisher ──JPEG──▶ mosquitto ──▶ analyzer (Station)      │   │ FastAPI backend       │   │ 홈 / 운동 / 기록     │
  (systemd 자동 시작)  ai_pt/cam/frame      · 자세 추정(YOLO)         │   │ · 영상(MJPEG) 중계     │◀─▶│                     │
                                            · 반복 카운트·판정        │   │ · 분석 정보 중계       │   │ 운동 탭:             │
                                            · 부위별 약점 계산        │   │ · 세션 시작/종료 명령  │   │  시작 · 종료 버튼    │
                                            └─▶ ai_pt/cam/analyzed ───┼──▶│                      │   │  관절선 영상 + 패널   │
                                            └─▶ ai_pt/cam/analysis ───┼──▶│                      │   │ 리포트·기록·홈       │
                                            ◀── ai_pt/cam/control ◀───┼───│ POST /camera/session/* │   └─────────────────────┘
                                            └─ HTTPS ─ 반복(+parts) ──┼──▶│ /workouts/* (DB 저장)  │
                                                       세션 열기/닫기   │   │ report · insights     │
                                      └──────────────────────────────────┘   └──────────────────────┘
```

| MQTT 토픽 | 방향 | 내용 |
|---|---|---|
| `ai_pt/cam/frame` | Pi → 분석기 | 원본 JPEG (QoS 0, 최신 한 장만 처리) |
| `ai_pt/cam/analyzed` | 분석기 → 서버 | 글자 없이 관절선만 그린 JPEG |
| `ai_pt/cam/analysis` | 분석기 → 서버 | 분석 정보 JSON (`session.state` = `idle` \| `active`, 방금 끝난 세션 `session.last` 포함) |
| `ai_pt/cam/control` | 서버 → 분석기 | `{"action":"start","exercise":"kneeup","plan":{"sets":3,"reps":10,"rest_seconds":60}}` (plan 생략 = 자유롭게) · `{"action":"stop"}` · `{"action":"skip_rest"}` · `{"exercise":"..."}` (QoS 1) |

세션 상태는 분석기(`station.py`)가 가진다: `idle ⇄ active(ready → working ⇄ resting)`. 분석 정보의 `session.progress`에 세트 번호·세트 내 횟수·남은 초가 실린다. 서버는 분석 정보의 `session`을 보고 시작/종료 요청을 받아 줄지 정한다.

## 부위별 약점

- 분석기가 반복마다 판정기가 **지적한 항목**만 보고 부위별 값을 계산한다 (`severity.rep_parts`). 지적이 없으면 0, 기준선을 막 넘으면 0.4, 확실히 벗어나면 1. 한 부위를 여러 조건이 말하면 가장 큰 값.
- 어느 조건이 어느 부위인지는 한 곳(`analyzer/aipt_analyzer/severity.py`)에서 정하고, 서버는 같은 대응을 `backend/app/modules/workouts/body_parts.py`에 둔다 (운동 설정 JSON을 바꾸면 함께 고친다).
- 세션/기간의 부위 약점은 반복(세션)들의 평균이다. 등급은 `양호`(0.15 미만) · `주의` · `보강 필요`(0.4 이상).
- 추세는 최근 세션을 앞·뒤 절반으로 나눠 약점 평균의 차이를 본다 (세션 4개부터). 약점이 거의 없는 부위의 미세한 변화는 말하지 않는다.
- 추천은 "가장 약한 부위가 가장 약하게 나온 운동 + 그 부위에서 가장 많이 지적된 문구"다. 약점이 없으면 한동안 안 한 운동, 기록이 없으면 푸시업.

## 한계

- 부위는 팔·몸통·다리 세 덩어리다 (좌우, 관절 단위는 아님). 얼굴/시선 지적은 몸통으로 센다.
- 점수와 약점은 합성 자세와 공개 데이터로 보정한 기준이다. 실제 사람이 움직이는 영상으로는 아직 검증하지 않았다.
- 기기가 하나라고 가정한다: 로그인한 누구나 시작/종료를 누를 수 있고, 분석기는 자기 계정으로 올린다.
