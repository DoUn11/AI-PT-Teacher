# 푸시업 피드백 개선 (짧은 설계)

## 왜
웹캠 테스트에서 푸시업 피드백이 기대대로 동작하지 않았다.
- "손을 가슴 옆에 두세요"(hand_position): 손을 한참 앞에 둬도 안 뜬다. 골반-어깨-팔꿈치 각도로 간접 측정해서 정면 카메라에서 거의 안 변한다.
- "손 간격을 너무 넓히지 마세요"(hand_width): 손을 넓게 짚어도 정상으로 처리된다. 기준이 손목 간격/어깨 간격 > 1.94배로 너무 느슨하고, '팔꿈치 90도' 라벨로 학습한 값이라 손 간격과 맞지 않는다.
- "더 깊이 내려가세요"(shallow_depth): 팔꿈치가 140°까지 안 내려가면 1회로 세지 않아 피드백도 안 나온다.

## 목표 / 비목표
- 목표: 손을 넓게 짚으면 경고, 얕게 내려가면 1회로 세고 "더 깊이 내려가세요" + 감점, 손 위치 피드백 삭제.
- 비목표: 손 간격 좁음, 어깨 수평 검사 (이번엔 안 함). AI Hub 데이터 재보정 (이 컴퓨터에 데이터 없음).
- 반목표: 팔을 편 상태의 흔들림이 1회로 세지는 것.

## 접근
- 고른 방식: 어깨·손목 점 위치로 직접 판정하는 고정 규칙. 설정(JSON) 기반 form_checks 구조를 그대로 확장한다.
- 버린 방식: 웹캠 녹화로 비율 기준을 다시 잡기 (규칙이 기하적이라 불필요), 숫자만 1.6~1.7로 낮추기 (기존 특징이 한쪽만 넓은 경우를 못 잡음).

## 설계 (사용자 승인)
1. 손 간격 넓음 `hand_width`: 새 특징 `hand_out` = 양손 중 더 큰 값 of (손목이 같은 쪽 어깨보다 바깥으로 나간 가로 거리 / 어깨 너비). 1회 평균 > 0.25면 위반, 실시간 경고 켬, 최대 20점. 메시지 "손을 어깨 너비로 짚으세요".
2. 더 내려가세요 `shallow_depth`: count_threshold 140 → 145 (up 150 유지). 목표 129.721° 유지, penalty_per_degree 2.0, min_score 60 (최대 40점 감점).
3. `hand_position` 조건·메시지 삭제.
4. 프론트(analysis.js)와 분석기(features.py)에 같은 특징, 두 pushup.json은 calibrate.py의 고정 조건(fixed_checks)·깊이 재정의로 생성되는 모양과 같게. 메시지, 테스트, 캐시 버전 갱신.

## 빌더 재량 (내 판단)
- full_at 0.5 (어깨 너비 절반 바깥에서 20점 전부) — 선형 감점.
- "바깥" 방향은 어깨 중점에서 각 어깨 쪽을 바깥으로 본다 (카메라 좌우 반전과 무관).
- 0.25, 145° 같은 수치는 출발값. 웹캠으로 써보고 조정.
